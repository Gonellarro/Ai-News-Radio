## Alcance funcional

- Recogida automática de noticias por RSS, páginas oficiales, Reddit, Mastodon,
  Bluesky y búsqueda complementaria con SearXNG, respetando sus intervalos.
- Redacción, resumen y traducción al español con Ollama local y atribución oral
  de la fuente al final de cada nuevo guion.
- Clonación de voz con Qwen TTS, generación por fragmentos lógicos, voces al azar,
  normalización de volumen, intros y pausas.
- Producción secuencial con reintentos limitados y reserva de candidatos sin
  redacción ni síntesis masiva.
- Parrilla rotativa con objetivo de veinte piezas y hasta diez trabajos
  seleccionados, además de los reintentos aplazados.
- Balanceo modular de fuentes con contadores históricos persistentes, pesos
  configurables y aprovechamiento de las fuentes que tengan material utilizable.
- Tarjetas estáticas por fuente, con colores, logos y textos sin paneles de fondo.
- Emisión local continua HLS y módulo opcional de salida a YouTube por RTMPS.
- Limpieza automática de los archivos de noticias retiradas.

Esta etiqueta identifica la base funcional instalada. La salida a YouTube requiere
la configuración y activación del directo; la etiqueta no acredita una emisión
pública ni la disponibilidad futura de todos los proveedores de noticias.

## Qué conserva Git y qué requiere copia de seguridad

Git conserva código, web, configuración pública, Dockerfiles, Compose,
documentación y pruebas ya existentes. La creación de esta versión no ejecuta
esas pruebas ni reconstruye o reinicia los servicios.

Quedan fuera `.env`, bases de datos, noticias y vídeos generados, registros,
claves de YouTube, modelos descargados, voces y grabaciones de referencia. También
quedan fuera los recursos operativos de `data/`, incluidas las intros y la biblioteca
local de logos. Conserva una copia aparte de esos datos para restaurar la instalación
exacta; Git por sí solo restaura el código y la configuración versionados.
Los originales de voces y datos privados no deben publicarse en un repositorio.

Los nombres actuales de las imágenes Docker son alias de construcción locales;
el identificador de esta versión de código es el tag Git de cada repositorio.

## Consultar esta versión

En cualquiera de las tres carpetas:

```bash
git log -1 --oneline
git show --no-patch v1.0.0
git rev-parse 'v1.0.0^{commit}'
```

Para consultar código anterior sin cambiar los archivos en uso:

```bash
git show v1.0.0:README.md
```

No cambies de versión en la carpeta activa mientras los contenedores de desarrollo
estén utilizando sus fuentes mediante volúmenes. Prepara otra carpeta o detén los
servicios antes de restaurar código o bases de datos de una versión anterior.
